# Vacant Land Redevelopment Explorer v1.0 Operational Handover

## Product entry points

- Dashboard: <https://rutomo-ura.github.io/land_redevelopment_dashboard/>
- URA Maps dashboard: <https://urap.maps.arcgis.com/apps/dashboards/9552e95d319b4e2180219ae66b3c8d65>
- Source web map: <https://urap.maps.arcgis.com/apps/mapviewer/index.html?webmap=19022018e35b4b72a2d30cba2d56c8e2>

The URA Maps dashboard is the canonical ArcGIS entry and embeds the deployed GitHub Pages app. It does not replace or modify LandCare.

## What is ready for use

- Map-first vacant-land review using tax delinquency, ownership, and vacant-lot score signals.
- Property-use, vacancy, and signal filters; neighborhood bookmarks; summary metrics; charts; and parcel detail popups.
- Table review, custom PIN-list matching, checked-parcel map preview, and PDF/XLSX export.
- Staff-review fallback data so the dashboard can still load when the ArcGIS parcel item is unavailable.

## Operating rules

1. Treat the dashboard as a review and prioritization workspace, not a determination of ownership, legal status, acquisition priority, or redevelopment eligibility.
2. Confirm parcel records, field conditions, zoning, program criteria, and ownership before action.
3. The current staff-review bundle includes owner names and EPP workflow fields. Keep protected notes, detailed account records, and connection details out of GitHub Pages, and move the app behind authenticated hosting before adding confidential data.
4. Publish only after `docs/latest_ownership_qa.md` reports `PASS`.

## Refresh and release

The production design is a 7:30 AM Eastern Windows Task Scheduler job on the secured GIS VM. It refreshes every source artifact, writes the manifest used by the in-app freshness panel, blocks publication on QA failure, and pushes changed data to GitHub Pages. Configure and verify it using [Daily Refresh VM Operations](daily-refresh-vm-operations.md). For a manual refresh, follow the root [README](../README.md#refresh-and-publish). A release is ready when the data checks pass, the deployed dashboard works for its intended audience, and the ArcGIS Dashboard loads the embedded app.
